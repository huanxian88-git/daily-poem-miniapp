## 一、研发自测体系

### 1.1 自测分层策略

| 层级 | 名称 | 范围 | 通过标准 | 责任人 | 工具 |
|------|------|------|---------|--------|------|
| **L1** | 单元自测 | 单个函数/方法级，含纯算法、工具函数、数据模型序列化 | 100% 分支覆盖，边界值通过，无异常抛出 | 开发（寇豆码） | pytest / 手动验证 |
| **L2** | 模块自测 | 服务/API级，含单个接口的请求-响应链、业务服务层方法 | 接口返回符合Schema，正常/异常路径均验证，数据库状态正确 | 开发（寇豆码） | httpx TestClient / Postman |
| **L3** | 联调自测 | 前后端联调，含页面→API→数据→渲染的完整链路 | 页面交互符合PRD，数据一致性，无Console错误 | 开发 + 刘宁配合真机 | 微信开发者工具 + 真机 |
| **L4** | 场景自测 | 端到端业务流，含跨模块场景、异常分支、边界条件 | 场景用例（SC-XXX）全部通过，数据在各模块间一致 | 刘宁主导 + 开发支持 | 真机 + 测试Checklist |

#### 分层通过门槛

```
L1 不通过 → 禁止提测，修复后重新自测
L2 不通过 → 可继续开发其他模块，但该接口不可进入联调
L3 不通过 → 禁止提交体验版，修复后重新联调
L4 不通过 → 禁止提交微信审核，修复后重新走查
```


```
    │

    │

    │   ├── 后端问题 → 后端修复 → 重新联调
```
